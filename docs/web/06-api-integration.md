This document lists the **web-consumed subset** of the shared platform contract, plus the web-only BFF routes. It is **not** a second API. The normative contract is `contracts/openapi/openapi.yaml` (contract-first, [ADR-0002](../adr/0002-contract-first-openapi.md)) together with `05-rest-api-specification.md` and `06-realtime-messaging-protocol.md`. All three are being written by the backend/contracts stream. Once they exist, **they win over this document** in every disagreement, and this document shrinks to web-specific notes (BFF, UI mapping, mock coverage). Shapes marked **(new)** are additions the web requests from that stream ([§10](#10-open-questions--requests-to-backend-stream)). Field names follow the PRD, the ERD and doc 07.

## 1. Conventions recap (doc 02 §5, normative)

| Concern | Rule |
|---|---|
| Base | `/v1`. JSON `snake_case`. Clients ignore unknown fields. |
| IDs | UUIDv7 lowercase strings (`Uuid` below). |
| Time | `Timestamp` = RFC 3339 UTC with `Z`. `LocalDate` = `YYYY-MM-DD` in the destination's IANA zone, carried as `time_zone`. |
| Pagination | `?limit=1..100` (default 20) and `?cursor=`. Response `Page<T>`. No offsets. |
| Errors | `application/problem+json` → `Problem`. Clients switch on `code`. `title`/`detail` are localized by `Accept-Language` (I18N-007). |
| Idempotency | `Idempotency-Key: <uuid>` on retried creates (marked **Idem**). Same key + different body → `409 idempotency_key_reused`. |
| Concurrency | Versioned aggregates return `version` and `ETag`. Updates send `If-Match` (marked **If-Match**). Mismatch → `412 precondition_failed`. |
| Auth | Server-side `Authorization: Bearer`. Browsers never send it; the BFF adds it (§3). |
| Locale | `Accept-Language` from the active web locale. |
| Correlation | `X-Request-ID` generated by the BFF if absent, echoed, and shown in error UIs. |
| Hidden resources | `404 not_found` instead of `403` wherever existence would leak. |
| Rate limits | `RateLimit-*` headers; `429 rate_limited` with `Retry-After`. Distinct from `429 quota_exceeded` (doc 07 §7). |

Auth column legend: **Public** (no session), **User** (any active session), **Verified** (session + verified email, AUTH-004), **E(key)** (entitlement or quota from doc 07), **Staff(Permission)** ([03 §4](03-roles-permissions.md#4-platform-roles-staff)).

Mock column legend: **Full** = implemented with realistic authorization outcomes; **Partial** = happy paths and key errors; **503** = returns `503 feature_not_available_in_mock` by policy (01 §7.1 rule 5); **—** = not yet.

  data: T[];

  | "conflict" | "precondition_failed" | "idempotency_key_reused" | "rate_limited"
  | "entitlement_required" | "feature_disabled" | "age_restricted" | "blocked_relationship"

  | "invitation_invalid" | "challenge_not_active" | "attempts_exhausted"

  | "email_unverified" | "connection_requests_restricted" | "discovery_invisible"

  | "account_suspended" | "ai_unavailable"
  // RESERVED, never emitted by the backend (doc 05): produced by the BFF or the client only

  | "session_expired";

  id: Uuid; destination_id: Uuid; slug: string; name: string; category: TravelCategory;

  store_grace_until: Timestamp | null;

  quotas: Record<QuotaKey, { limit: number; used: number; resets_at: Timestamp | null }>;

## 3. BFF contract (web-only route handlers, not part of `/v1`)

All BFF responses carry `Cache-Control: private, no-store` and `X-Request-ID`. Non-safe methods require the CSRF header and same-origin checks ([ADR-0011](../adr/0011-web-bff-cookie-sessions.md) §5). A CSRF failure returns `403` with `code: "csrf_failed"`, a reserved code the backend never emits.

| Route | Request | Success | Errors | Notes |
|---|---|---|---|---|
| `GET /api/auth/login` | `?intent=login\|signup&provider=google\|apple\|email&next=<relative path>` | `302` to the IdP authorize URL (`provider` becomes an IdP connection hint), or to `/dev/login` in dev; sets `tb_oidc` (`state`, `nonce`, PKCE verifier, intent, `next`) | `400 validation_failed` (unknown provider, absolute or protocol-relative `next`) | `next` must start with `/` and not `//`; otherwise `/feed`. |
| `GET /api/auth/callback` | `?code&state` (or `?error`) | `302` to `next`, or `/onboarding` if not onboarded; sets `tb_session`, rotates `tb_csrf`, clears `tb_oidc` | `302 /auth/error?code=` for `state` mismatch, IdP error, `account_suspended`, `age_restricted`, `service_unavailable` | Login: `POST /v1/auth/login {id_token, client:"web", nonce}`. On `404 not_found` (no account) for a login intent → `/register?continue=1`. Signup: `POST /v1/auth/register` with the `birth_date` and consent versions collected on `/register` (carried sealed in `tb_oidc`). |
| `POST /api/auth/dev` | form/JSON `{persona_id} \| {sub, email, name, birth_date, intent}`, `next` | `303` to `next` or `/onboarding`; sets cookies | `404` unless `DevIdentityProvider` is active | Calls `POST /v1/dev/idp/token` (or the mock's equivalent), then the **same** login/register path as production (ADR-0011). |
| `POST /api/auth/logout` | — (CSRF) | `204`, or `303` to the IdP end-session endpoint with `?federated=1` | — (cookies are always cleared) | Calls `POST /v1/auth/logout` best-effort. |
| `GET /api/auth/session` | — | `200 { authenticated: false }` or `{ authenticated: true, viewer: ViewerSummary }` | — | `ViewerSummary = { id, handle, display_name, avatar_url, roles, plan, email_verified, onboarding_completed }`. Never returns tokens. |
| `ALL /api/v1/[...path]` | Mirrors `/v1/...`; JSON body ≤ 1 MB (media goes direct to object storage); query passthrough | Upstream status/body; strips `set-cookie` and hop-by-hop headers; `X-TB-Mock: 1` in mock mode | `401 session_expired` (no cookie or refresh failed; cookie cleared), `403 csrf_failed`, `405`, `413 payload_too_large`, `502/503 service_unavailable` | Methods: GET, POST, PUT, PATCH, DELETE. Path allow-list `^[a-z0-9\-_/]+$`, no `..`. `/v1/admin/**` is proxied only for sessions holding a platform role. `/v1/dev/**` is never proxied. `near`, `lat`, `lng` are redacted from logs. SSE responses are streamed unbuffered. |
| `POST /api/realtime/ticket` | — (CSRF) | `200 { ticket, url, expires_at }` | `401 session_expired`, `503 service_unavailable` (`503 feature_not_available_in_mock` in mock) | Wraps `POST /v1/realtime/tickets`. |
| `GET /api/health` | — | `200 { status: "ok", version, api_mode: "mock"\|"live" }` | — | Liveness only. |

## 5. Realtime frames used by the web

Transport: `wss://{REALTIME_URL}/v1/realtime`. The normative protocol and JSON Schemas are `06-realtime-messaging-protocol.md` and `contracts/realtime/` (backend stream, in progress). The web uses this subset:

| Direction | Frame | Payload | Web handling |
|---|---|---|---|
| C→S | `auth` | `{ type: "auth", ticket }` within 5 s of open. The gateway accepts `access_token` (mobile) **or** `ticket` (web) (ADR-0013) | Ticket from `POST /api/realtime/ticket` |
| S→C | `auth.ok` / `auth.error` | `{ user_id, session_id, server_time }` / `{ code }` | `auth.error` → fetch a new ticket once, then back off |
| C→S | `message.send` | `{ client_message_id, conversation_id, body?, attachment_media_ids?, reply_to_id?, mentions? }` | Optimistic message with status `sending` |
| S→C | `message.ack` | `{ client_message_id, id, seq, created_at }` | Replace the optimistic message; status `sent` |
| S→C | `message.nack` | `{ client_message_id, code }` | Status `failed` + Retry (same `client_message_id`) |
| S→C | `message.new` / `message.updated` / `message.deleted` | `Message` / `{ id, conversation_id, seq }` | Write into the TanStack Query cache; dedupe by `id`; if `seq > last_seq + 1`, catch up via REST `after_seq` (DM-006) |
| C→S / S→C | `typing.start` / `typing` | `{ conversation_id }` / `{ conversation_id, user_id, expires_at }` | Send at most once per 3 s; indicator expires at 8 s |
| C→S | `receipt.read` | `{ conversation_id, seq }` | Only when the conversation is visible and focused, and only if `read_receipts_enabled` |
| S→C | `receipt.updated` | `{ conversation_id, user_id, read_seq, delivered_seq }` | Delivery/read ticks (direct chats, reciprocal) |
| S→C | `reaction.updated` | `{ message_id, reactions }` | Patch the cache |
| S→C | `membership.changed` / `conversation.updated` | `{ conversation_id, … }` | Invalidate; if removed, close the view with an explanation (GCHAT-007) |
| S→C | `notification.new` | `Notification` | Badge count, toast if visible |
| S→C | `resync.required` | `{ scope: "all" \| conversation_id }` | Refetch the affected queries |
| S→C | `session.revoked` | `{ reason }` | Close the socket, call `/api/auth/session`, redirect to `/login` |
| both | `ping` / `pong` | `{}` | Every 25 s; 2 missed pongs → reconnect |

Reconnect: exponential backoff with full jitter (1 s → 30 s cap), a new ticket per attempt, then per-open-conversation catch-up. After the tab has been hidden for 5 minutes the socket is closed, and Web Push covers the gap.

## 6. API client behaviour (`@travelbuddy/api-client`)

| Behaviour | Implementation |
|---|---|
| Errors | Non-2xx → `ApiError { status, code, title, detail, request_id, fieldErrors, entitlement?, quota?, limit?, resets_at? }`. A non-problem body becomes `service_unavailable` (5xx) or `unknown`. A network failure becomes `ApiError { status: 0, code: "network_error" }` (reserved; client-only). |
| Retries | Automatic only for idempotent requests (GET, PUT, DELETE, and POST with `Idempotency-Key`), on network errors, `502/503/504` and `429 rate_limited` (honouring `Retry-After`). Max 2 retries, jittered. **Never** on `429 quota_exceeded`. |
| Idempotency keys | Generated per *user intent* (for example per composer submission) and reused across retries of that intent. |
| Cursor pages | No unbounded "fetch all" helpers for user data. Infinite queries use `page.next_cursor`; `page.reset` replaces the cache. |
| Timeouts | 10 s default via `AbortSignal.timeout`; 30 s for upload finalize; SSE uses a 30 s idle timeout. |
| Response guards | Critical responses (session, `MyAccount`, entitlements, feed) are parsed with Zod schemas from `@travelbuddy/validation` in development and test builds to catch contract drift early. Production skips them. |
| Locale | The transport adds `Accept-Language` from the active locale. |

## 9. Contract governance

1. **Source of truth:** `contracts/openapi/openapi.yaml` (ADR-0002), owned by the backend/contracts stream. This document covers the web-consumed subset only and defers to the spec once it exists. Web-originated changes are **requested** from that stream (§10), never edited directly into the spec by the web.
2. **Generation:** `npm run contracts:generate` runs `openapi-typescript` → `packages/domain-types/src/generated.ts`. Hand-written types become aliases (`type Post = components["schemas"]["Post"]`).
3. **Drift checks in `ci-web.yml`:** regenerate types and fail on a non-empty diff. Every mock route must exist in the spec, and mock fixture responses must validate against the spec schemas.
4. **Contract tests:** the backend runs schemathesis against the spec (doc 10 §1). The web runs API-client tests against fixtures validated by the same schemas.
5. **Change rules:** additive changes (new optional fields, endpoints, enum values with a documented client fallback) ship in `/v1`. Clients ignore unknown fields and map unknown enum values to a safe default. Removals, renames, tightened validation or changed semantics require `/v2` or a deprecation cycle.
6. **Deprecation:** marked in OpenAPI, with `Deprecation` and `Sunset` headers, kept for at least 2 mobile release cycles, and removed only when telemetry shows < 1 % usage.
7. **(new)** items below must land in the spec before the dependent web feature ships to staging.
